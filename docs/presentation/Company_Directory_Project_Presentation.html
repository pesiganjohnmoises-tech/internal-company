Company Directory · Project presentation
1 · Executive overview

One place to find the right agent — and the right person to contact

What it is

An internal web application that holds our overseas partner agents (freight forwarders) by country, with their contacts, network memberships, status and assigned sales reps.

Who uses it

Staff who need to find and contact agents. Each account sees only the countries, companies and sales columns granted to it.

Who manages it

An administrator, who loads country workbooks from Excel, manages user accounts and access, and monitors data quality.

Status

Live Running on PythonAnywhere with automatic deployment from GitHub.

137agent companies · 474 contacts
4countries — India (107 companies, real data); Singapore, Thailand, USA (10 sample records each)
8user accounts · 3 access levels

2 · Business problem

Agent information lived in spreadsheets

The system imports one Excel workbook per country. The problems below are the ones its features are built to solve.

Scattered by country

Each country's agents sit in a separate workbook, so finding "an agent in Chennai on WCA" means opening and searching several files.

All-or-nothing sharing

A shared workbook exposes every column to everyone — including which rep from which of our brands handles each agent.

Manual status checks

Expired network memberships, pending KYC and inactive agents must be spotted by reading dates and statuses row by row.

Uneven data quality

Missing emails and phones, shared addresses and unreadable dates are hard to see across hundreds of rows.

Risky updates

Replacing a country's data by hand can silently drop or duplicate companies, with no record of who changed what.

Slow to reach people

Once the agent is found, the right contact's email or phone still has to be located and copied from another sheet or cell.

4 · Key features

For the administrator: control, safety and oversight

Users & access

  • Three levels: User, Full Access, Admin
  • Per-country access with "All companies, including future imports" or hand-picked companies
  • Per-user visibility of the four brand sales columns
  • Users list shows last sign-in and how many companies each person can see

Safe Excel imports

  • Preview before anything changes: new, removed and updated companies, skipped rows
  • Automatic database backup before every import (newest 10 kept)
  • Company IDs and user access survive re-imports
  • Failed imports roll back and are recorded

Overview dashboard

  • Needs attention: expired / expiring networks, KYC pending, inactive agents, unreadable dates
  • Contact data quality, sales-rep coverage per brand, access overview
  • Import health and recent admin activity

Records & exports

  • Records page: every company with source file and row, filters and paging
  • CSV export of companies (all workbook columns) and contacts, safe to open in Excel

9 · Data structure

How the information is organised

Every Excel column is kept

Besides the main fields, each company and contact stores its full original row, so new workbook columns appear on the profile without programming.

Access lives with the data

Grants link user accounts to countries and companies; the database answers only with rows a user may see.

Passwords are stored only as one-way hashes. No credentials or keys are shown in this document.

10 · Security

Security: in place today, and recommended next

Implemented

  • Personal accounts; passwords stored as strong one-way hashes (scrypt); minimum 12 characters
  • Sign-in throttling: 5 failures per user/address, 30 per address, 15-minute lock
  • Sessions end after 2 h idle / 12 h total; a password change signs out every other session
  • Access checks built into every database query (country, company, sales columns)
  • Form protection against cross-site request forgery
  • Secure, HTTP-only session cookies (confirmed on the live site)
  • Browser security headers (no framing by other sites, no content sniffing)
  • Uploads limited to .xlsx up to 16 MB; file names sanitised
  • CSV exports neutralise spreadsheet formulas; log lines cannot be forged
  • Deploy endpoint accepts only GitHub requests signed with a shared secret

Recommended

  • Force HTTPS on the host — plain http was not redirected when checked on 25 Sep
  • Repository history: the first commit included a database copy and an old key; keep the repository private or clean its history
  • Default accounts: confirm the seeded passwords were changed (the overview warns if not)
  • Run the automated tests before every deploy
  • Keep an off-site copy of database backups

11 · Performance & reliability

Fast for today's data, safe when things go wrong

Performance (in place)

  • Database indexes on company name, agent ID, contact name, email and phone
  • Paged results (20 per search page, 50 per records page); long searches capped
  • Slow password checks done once, not on every overview load (~300 ms → ~65 ms, measured locally)
  • Signed-in user looked up once per request
  • Server-rendered pages with one small script and one stylesheet

Reliability (in place)

  • Imports run as one transaction: a failure leaves the previous data untouched
  • Automatic backup before each import; newest 10 kept
  • A failing overview panel shows a notice instead of breaking the page
  • Friendly pages for expired forms, oversized uploads and server errors
  • Activity log rotates at 1 MB so it cannot fill the disk
  • 209 automated checks covering access rules, imports, security fixes and screens

Page timings were measured on a laptop against a copy of the database; live response times on the host are Not verified.

15 · Business impact

Value to the business

Time saved

One search across all countries replaces opening several workbooks; contacts can be emailed, called or copied directly.

Controlled information

Each person sees only what they need; commercial columns stay with the people entitled to them.

Fewer mistakes

Status on every result; on the snapshot date the overview surfaced 38 attention items in the real India data (expired or expiring networks, inactive agents, unreadable dates).

Less admin work

Imports are previewed and backed up; "All companies" access removes re-granting after every import; users reset their own passwords.

Scalable

New countries are added by uploading a workbook — no code change; new columns appear automatically.

Maintainable

Small, standard technology; changes go live automatically after a push; 209 automated checks guard behaviour.

Benefits are qualitative. No time or cost savings have been measured, so none are claimed.
